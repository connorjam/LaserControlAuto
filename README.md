# 激光控制自动化 · LaserControlAuto

在激光驱动调试软件里自动逐点设置参数，等稳定后到测量软件读取数值，全部记录到 CSV。

由 **[MaaFramework](https://github.com/MaaXYZ/MaaFramework)** 驱动

</div>

---

## 它做什么

一句话：**改一个参数 → 等一会儿 → 读一个数 → 记一行 → 换下一个参数**，循环到扫完为止。

具体流程：

| 步骤 | 动作 |
| --- | --- |
| 1 | 在 **A 软件** 里**现场 OCR 定位**目标参数那一行（默认标签 `Temperature`；有同名标签时用 `near_text` 指定要哪个），清空输入框、填入本轮数值，再点同一行的 `Setting` |
| 2 | 等待一段时间（默认 10 秒），让设备稳定下来 |
| 3 | 到 **B 软件** 里读指定标签**旁边**的数值（默认标签 `功率CH1`；标签右边同一行、或标签正下方都认） |
| 4 | 把「序号 / 设定参数 / 测量值 / 时间」追加写入 CSV |
| 5 | 换下一个参数，回到第 1 步 |

扫描区间、**步长或点数**、等待时间和结果保存位置都可以在界面上直接填，不用改代码。

## 怎么用（最终用户）

### 运行前准备

1. **Windows 10/11 64 位**电脑
2. 装上 [VC++ 运行库](https://aka.ms/vs/17/release/vc_redist.x64.exe)
   （缺了会报「应用程序无法正常启动」）
3. （若提示缺少 .NET）安装 [.NET Desktop Runtime](https://dotnet.microsoft.com/download/dotnet)
4. **打开 A 软件和 B 软件**，让它们都停在工作界面上

> Python 不需要自己装——发布包里已经带了一份便携版解释器。

### 操作步骤

1. 解压发布包，双击 `MFAAvalonia.exe`
2. 控制器选 **「桌面端」**，资源选 **「默认」**
3. 在 **「扫描设置」** 里填：
   - **起始值 / 结束值**：扫描区间，例如 20 到 30
   - **步长**：每一步加多少，例如 1（也可以填 0.5）
   - **扫描点数**：一共扫几个点 —— 填 `0`（默认）就按上面的步长算；填 `>0` 就以点数为准（见下面「按步长还是按点数」）
   - **每轮等待秒数**：设好参数后等多久再读数，例如 10
   - **结果文件夹名 / 结果文件名 / 跑完自动打开 / 输出总目录**：见下面「结果存到哪儿」
4. 勾选任务 **「激光参数扫描」**，点开始
5. 跑完会自动弹出 `output` 文件夹（可以关掉），到里面按时间取本次的 CSV（文件名自带扫描参数）

> ⚠️ 任务运行期间**不要用手去动鼠标键盘**，程序会自己操作 A 软件。
> 想中途停止，按界面上的停止按钮即可。

### 结果存到哪儿

所有结果都放在**软件所在文件夹**的 `output/` 里，每次扫描各占一个子文件夹：

```tree
MFAAvalonia.exe
output/
├── 20261016_110530_output/                       ← 默认名 = 系统时间（到秒）
│   └── 20261016_110530_20_30_11.csv              ← 默认名 = 时间_起始值_终止值_总点数
└── 20261016_143012_升温测试/                      ← 文件夹也可以自己起名
    └── 升温测试结果.csv                            ← 文件名也可以自己起名
```

| 界面上的项 | 作用 | 默认 |
| --- | --- | --- |
| **结果文件夹名** | 本次结果放在 `output/` 下的哪个子文件夹 | 留空 = `系统时间_output`，如 `20261016_110530_output` |
| **结果文件名** | CSV 叫什么 | 留空 = `时间_起始值_终止值_总点数`，如 `20261016_110530_20_30_11` |
| **跑完自动打开** | 扫描结束后自动弹出 `output` 文件夹 | 开 |
| **输出总目录** | 把 `output/` 整个换到别处 | `output` |

**默认文件名**把这次扫的参数直接写进名字里，翻 `output/` 时不用逐个打开就知道是哪个扫描：

| 扫描设置 | 默认文件名 |
| --- | --- |
| 20 → 30，步长 1（11 组） | `20261016_110530_20_30_11.csv` |
| 20.5 → 21，2 组 | `20261016_110530_20.5_21_2.csv` |
| -10 → 0，3 组 | `20261016_110530_-10_0_3.csv` |

> 名字里的「总点数」是**实际跑了几组**（按步长算出来的那个数），
> 不是界面上「扫描点数」填的值 —— 这样名字和 CSV 里的行数一定对得上。

**结果文件夹名 / 结果文件名**都支持几种写时间的方式，混着中文写也行：

| 写法 | 展开成 |
| --- | --- |
| `%Y%m%d` | `20261016` |
| `{date}` / `{time}` / `{datetime}` | `20261016` / `110530` / `20261016_110530` |
| `升温_%Y%m%d` | `升温_20261016` |

> 文件夹名 / 文件名里的 `\ / : * ? " < > |` 会被自动换成 `_`
> （Windows 不允许这些字符，直接拿去建目录会报错），中文和空格照常保留。

### 想随时打开 output 文件夹

任务列表里有一个 **「打开输出文件夹」** 任务 —— 勾上它点开始，就会弹出 `output` 文件夹：

- 扫描**做完了**想再看一眼结果：直接用它，打开的就是上次实际用的那个目录（
  就算把「输出总目录」改成了 `D:\扫描数据` 也认得）；
- 扫描**还没跑过**：也能用，会打开默认的 `output/`（不存在就现建一个空的）。

> 为什么是「一个任务」而不是一个按钮：Project Interface V2 协议的配置项只有
> 输入框 / 下拉 / 勾选 / 开关 / 快捷键五种，**没有按钮控件**，
> 所以这里用一个「点一下就弹文件夹」的任务来充当按钮。
> 它同样需要控制器连接成功（通用 UI 的前置条件），但不要求 A/B 软件开着。

### 结果长什么样

CSV 内容（UTF-8 BOM 编码，Excel 双击不乱码）：

| 序号 | 设定参数 | B软件测量值 | 时间 |
| --- | --- | --- | --- |
| 1 | 20 | -79.72 | 2026-09-22 16:51:25 |
| 2 | 25 | -79.94 | 2026-09-22 16:51:32 |
| 3 | 30 | -80.11 | 2026-09-22 16:51:58 |

（数值随设定参数变化，这里只是示意；GaussianBeam 那类 B 软件读到的会是 `1061` 这样的波长值。）

某一轮读数失败时会写一行空值占位，保证行号和参数一一对应，不会错位。

## 按步长还是按点数

扫描点的生成有**两种模式**，由「扫描点数」这个输入框决定：

| 「扫描点数」填什么 | 走哪种模式 | 例子（起始 20、结束 30） |
| --- | --- | --- |
| `0`（默认）或留空 | **按步长** —— 用多少步长就多少，点数由区间算出来 | 步长 1 → 11 个点；步长 0.5 → 21 个点 |
| `>0` | **按点数** —— 就扫这么多点，步长自动反算（此时**忽略「步长」**） | 填 11 → 步长 1；填 6 → 每步 2；填 3 → 每步 5；填 1 → 只扫起始值 |

按点数时，步长 = `(结束值 - 起始值) ÷ (点数 - 1)`，**最后一个点一定落在结束值上**：

```text
起始 20、结束 30、点数 6  →  20, 22, 24, 26, 28, 30      （每步 2）
起始 20、结束 30、点数 4  →  20, 23.333333, 26.666667, 30 （每步 10/3，除不尽）
```

> 「除不尽」是完全可以用的：步长就按反算出来的小数严格走，点数照样走满。
> 只是 A 软件输入框里会出现 `23.333333` 这种长小数 ——
> 想让每个点都是"整齐"的数，就把 `区间 ÷ (点数-1)` 凑成整数
> （例如 20→30 想每步 2，就填 6 个点；想每步 2.5，就填 5 个点）。

两种模式在运行日志里都写得明明白白，跑完对照一眼就知道用的是哪个：

```text
[laser_sweep] 参数序列共 11 组：20 → 30（按步长（1））
[laser_sweep] 参数序列共 6 组：20 → 30（按点数（6 个点，反算步长 2））
```

> **老配置不会受影响**：不填「扫描点数」和填 `0` 是同一条路，
> 生成的点与升级前**完全一致**。

## 跑一轮要多久 / 想更快怎么调

一轮（设一个参数 → 等稳定 → 读一个数 → 记一行）在本机（1331x720 窗口）实测：

| 环节 | 优化前 | 现在 |
| --- | --- | --- |
| 全屏 OCR 找 `Temperature` / `Setting` | 4.57 秒 × 2（中位） | **只第一轮 1 次**，之后复用缓存 |
| 等设备稳定（界面上的「每轮等待秒数」） | 10 秒 | 10 秒（这是唯一"该等"的时间） |
| 读 B 软件（截图 + OCR） | 5.54 秒 | 5.54 秒 |
| 清空输入框（退格 32 次） | 约 4.1 秒 | 约 1.5 秒（12 次） |
| 等画面冻结 + 余量 | 约 4.3 秒 | 0.2 秒 |
| 点击 / 输入 / 框架调度 | 约 1.1 秒 | 约 1.1 秒 |
| **合计** | **约 34 秒/轮** | **约 18 秒/轮** |

> 第一轮会慢一点（约 23 秒），因为它要 OCR 一次来建立定位缓存。
> 扫描 20→30、步长 1 共 11 组：原来约 6.3 分钟，现在约 3.5 分钟。

想再压时间，按收益从大到小：

1. **「每轮等待秒数」**：设备实际多久稳定就填多少。这一项每减 1 秒，整轮就省 1 秒。
2. **定位缓存**（`my_task.json` 里 `LaserSweepFindTemperature` / `LaserSweepClickSetting`
   的 `custom_recognition_param`）——默认「第一次 OCR、之后全程复用」，可选：

   | 参数 | 默认 | 含义 |
   | --- | --- | --- |
   | `use_cache` | `true` | 写 `false` 就退回「每次都重新 OCR」的老行为 |
   | `cache_ttl` | `600` | 缓存最长用多久（秒），`0` = 不因时间失效 |
   | `relocate_every` | `0` | 每复用几次强制重认一遍；长跑怕跑偏可以写 `20` |
   | `hint_roi_pad` | `240` | 缓存失效后重定位时，先用「上次位置外扩」的小 ROI 试一把 |

   缓存会在**截图尺寸变化**（窗口被挪/被缩放）时自动作废，不会拿旧坐标去点。
3. **`LaserSweepClearField` 的 `repeat`**：够清掉输入框里的旧值就行。
   日志里若发现数值被拼接（如 `20.525`），说明有残留，把它调回 32。

日志里怎么确认缓存生效：

```text
[laser_sweep]   📌 已缓存 A 软件控件位置：anchor=[497, 293, 95, 16]；target=[726, 292, 61, 20]；input=[592, 292, 134, 20]
[laser_sweep]   ♻️ 复用定位缓存（return_box=input）[592, 292, 134, 20]；已复用 3 次，缓存 12 秒
```

> 节点与节点之间**没有**额外的人为间隔。框架自带的默认值
> （`rate_limit` 1000 毫秒、`pre_delay` / `post_delay` 各 200 毫秒）
> 已在流水线里逐个显式压成 0，改慢改快都只看上面这几项。

## 出问题了怎么办

| 现象 | 可能原因 / 处理 |
| --- | --- |
| 打开后「任务列表」是空的，点 + 也没任务可加 | `interface.json` 没加载成功：日志里会有「文件 interface.json 加载失败！」。常见原因是 `welcome` 写成了字符串数组，见[打包文档的常见问题](docs/zh_cn/develop/packaging.md) |
| 点了开始没反应，A 软件没被操作 | 检查 A 软件是否已打开、窗口标题是否和配置一致 |
| 提示找不到窗口 | 窗口标题变了，见下面「换成别的软件」 |
| 数值一直读不到 | B 软件窗口没开，或者标签文字不对 |
| CSV 里测量值全是空的 | 读数失败，看日志里的 OCR 结果 |
| A 软件的参数没被改，或点到别处去了 | 看日志面板里 `[laser_sweep]` 那几行：`锚点候选` / `按钮候选` / `点击 (x, y)` 会说明它选了谁、点在哪；选错就用 `near_text` 指定标签 |
| 改了定位缓存之后点偏了 | 缓存只在**截图尺寸没变**时复用，窗口被挪过就会自动重认。若仍怀疑它拿旧坐标硬点，把节点的 `use_cache` 写成 `false` 退回老行为（见上面「跑一轮要多久」） |
| 快起来之后数值被拼接（如 `20.525`） | 退格次数不够清空输入框，把 `LaserSweepClearField.repeat` 调回 32 |
| 日志里一条 `[laser_sweep]` 都没有 | 用的是 v1.0.4 之前的老包（stdout 被块缓冲吃掉，打印刷不出来），换新版即可 |
| 报「应用程序无法正常启动」 | 装 VC++ 运行库 |

日志位置：通用 UI 的运行日志面板（agent 的调试打印都以 `[laser_sweep]` 开头），
以及 `debug/maafw.log`（框架层细节）。

## 换成别的软件（改配置）

### 换 B 软件（要读数的那个）—— 改 2 处

编辑 `resource/pipeline/my_task.json`，找到 `LaserSweepReadValueB`：

```jsonc
// ① 窗口标题（用 ^...$ 锚定；多套软件可以用 | 一次写全）
"window_regex": "^(GaussianBeam|光器件耦合系统.*)$",
// ② 要读的那个量的标签，可以写数组（任一命中即可）
"anchor_text": ["功率CH1", "Wavelength"],
```

数值是靠**位置**认的，程序自己会挑：

1. 先找「标签**右边、同一行**」的数值 —— 光器件耦合系统那种 `功率CH1 │ -79.720dBm` 的排法；
2. 再找「标签**正下方**」的数值 —— GaussianBeam 那种 `Wavelength` 换行接 `1061 nm` 的排法；
3. 两条都不成立，才退回「离标签最近」并打警告（结果未必准）。

> ⚠️ 别把 `anchor_text` 写成 `"CH1"` 这种既当标签、自身又含数字的词。
> 宽松正则在标签自己身上就能匹配出 `1` —— 换电脑后实测踩过这个坑：测量值恒为 1。
> 现在有「候选不许和标签重叠」这条护栏兜着，但标签写得越明确越稳。

> `window_regex` 要加 `^...$`。比如标题叫 `GaussianBeam` 时，
> 不加锚点会连「GaussianBeam - 文件资源管理器」一起匹配上。

### 换 A 软件（要操作的那个）—— 改 2 处

| 改哪儿 | 改成什么 |
| --- | --- |
| `interface.json` → `controller[].win32.window_regex` | A 软件的窗口标题 |
| `my_task.json` → `LaserSweepFindTemperature` 的 `anchor_text` | 参数的标签文字 |
| （可选）`LaserSweepFindTemperature` 的 `near_text` | 界面上有多个同名标签时，钦定「离它最近」的那一个 |

**不需要量任何坐标、比例或 `roi`**：

- 「标签」和它那一行的 `Setting` 按钮由**配对法**锁定，界面上有同名文字也认不错行；
- 输入框位置是**每次点击前现场 OCR 夹出来的**：取「标签右边界 → 按钮左边界」之间那块文字
  （也就是输入框里的当前值），中间没文字就取两者中点。

所以窗口大小、分辨率、DPI 怎么变都不用改配置。
（v1.0.2 之前是「标签中心 + 窗口宽度 × 比例」，换台电脑窗口一小就点偏了。）

**界面里有多个同名标签时**（比如两个 `Temperature`），告诉程序该用哪一个：

```jsonc
"anchor_text": "Temperature",
"near_text": ["Module Config", "ModuleConfig"],  // 取「离它最近」的那个标签
// 或者干脆数着来：
// "anchor_index": 1,                            // 从上到下第 2 个（0 = 第一个）
```

`near_text` 没命中时日志里会打 ⚠️ 并退回旧逻辑；每次运行还会打印
`锚点候选：...` 和 `按 near_text=... 钦定锚点 ...`，对着日志就能确认选对没有。

> **标签、按钮、数值三者都只认「短文本」**
> （`anchor_max_chars` / `target_max_chars` / `value_max_chars` / `min_digit_ratio`）。
> 界面上的 Tips、日志行动辄几十个字，只要含关键词就会冒充成标签、按钮或数值。
> 2026-09-22 换电脑后连吃两次：`Start Wavelength 1548.000000rm not in range[...]`
> 冒充成 B 软件的标签；而 `Tips：Setting TEC Temperature Successfully!`
> 一行**同时**冒充了 A 软件的标签和 `Setting` 按钮 —— 它俩的关键词都在里面，
> 距离还比真控件近。
>
> 日志里 `锚点候选` / `按钮候选` 会列出过滤后的名单，
> 跑一轮就知道有没有漏网的。

## 给开发者：怎么打包

见 [`docs/zh_cn/develop/packaging.md`](./docs/zh_cn/develop/packaging.md)。

两条路：

- **本地打包**：准备 `deps/`（MaaFramework）+ `MFA/`（MFAAvalonia），
  跑 `python tools/prepare_embedded_python.py`，再跑 `python tools/install.py v1.0.5 win x86_64`，
  最后 `python tools/pack_zip.py` 打出 `dist/LaserControlAuto-win-x86_64-v1.0.5.zip`
- **CI 自动打包**：打一个 `v1.0.5` 标签推上去，
  GitHub Actions 会自动打包 **Windows x64 版**并创建 Release

> 只是修了 agent / 流水线 / 界面配置时，不必重发整个包 —— 用**热修复包**更快
> （几十 KB，使用者解压覆盖即可）：
>
> ```bash
> python tools/pack_hotfix.py v1.0.6
> ```
>
> 产物 `dist/LaserControlAuto-v1.0.6-hotfix-files.zip` 里是这三样：
>
> | 文件 | 管什么 |
> | --- | --- |
> | `agent/laser_sweep.py` | 逻辑：定位、读数、扫参序列 |
> | `resource/pipeline/my_task.json` | 流程：节点、延时、默认参数 |
> | `interface.json` | **界面：UI 输入项 + `pipeline_override`** |
>
> 解压后覆盖到 `MFAAvalonia.exe` 那一层。脚本会打印每个文件的字节数与 md5，
> 使用者对着运行日志里那行 `[laser_sweep] agent 文件：…（字节数，改于 …）`
> 就能确认换成功没有。
>
> ⚠️ **`interface.json` 别漏**（2026-10-14 踩过）：
> UI 上的「扫描设置」输入框全都定义在 `interface.json` 的 `option.*.inputs` 里，
> agent 和 pipeline 只是**接收方**。只覆盖前两个的话，新增的输入项
> （比如「扫描点数」）在别的电脑上**根本不会出现**——而本机因为 `install/`
> 早被 `install.py` 重写过，看着却是好好的，很容易误判成"热修复没生效"。
> 一句话：**动了 UI 输入项或 `pipeline_override`，就必须连 `interface.json` 一起发。**
> （`tools/pack_hotfix.py` 的 `DEFAULT_FILES` 现在已默认包含它。）
>
> 打包源是 `install/` 里的副本（跟 `pack_zip.py` 一致）。由于 `install/` 是
> `tools/install.py` 从 `agent/`、`assets/resource/` 拷过去的，脚本会先比一遍：
> 两边不一致就停下并告诉你怎么处理（`--sync` 让它就地同步，`--force` 按现状强打）。
> `interface.json` 不参与这项比对 —— 它本来就该和 `assets/interface.json` 不同
> （版本号、agent 路径、welcome 都被 `install.py` 改写过了）。

## 目录结构

```
LaserControlAuto/
├── assets/
│   ├── interface.json              ← 界面配置：窗口、任务、可填参数
│   └── resource/
│       ├── pipeline/my_task.json   ← 主流程（改这里调流程）
│       ├── image/                  ← 找图用的模板图
│       └── model/ocr/              ← OCR 模型
├── agent/
│   ├── main.py                     ← AgentServer 入口
│   └── laser_sweep.py              ← 自定义识别 / 动作（核心逻辑）
├── tools/
│   ├── install.py                  ← 打包脚本
│   ├── pack_zip.py                 ← 把 install/ 打成 dist/ 里的发布 zip
│   ├── pack_hotfix.py              ← 只把要覆盖的几个文件打成热修复包
│   ├── prepare_embedded_python.py  ← 准备便携版 Python
│   ├── check_pickers.py            ← 定位逻辑自检（不连软件，改完跑一下）
│   └── configure.py                ← OCR 模型配置
├── docs/                           ← 文档
└── .github/workflows/              ← CI：检查 + 自动发版
```
